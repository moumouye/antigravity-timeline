# ③ 否决与避坑档案 (Anti-Patterns & Dead Ends)

本文档记录系统演进中经过实测否决的技术方案与反模式（Anti-Patterns），禁止在后续开发演进中重新引入。

---

## 避坑总览表

| 否决方案编号 | 方案名称 | 致命缺陷现象 | 真实技术根因 | 唯一合法解决方案 |
| :--- | :--- | :--- | :--- | :--- |
| **AP-01** | **纯前端 DOM 刮取** | 长对话时间线残缺，只能看到最后 2~3 轮。 | 宿主原生实现了虚拟化列表与顶部消息冷折叠，早期历史根本不在前端 DOM 树上。 | **底层直通**：由 Sidecar 读取底层 `transcript.jsonl`，获得 100% 完整会话。 |
| **AP-02** | **悬停/启动时模拟点击展开** | 鼠标一放上去，画面瞬间跳回第 2 轮；滚动条剧烈伸缩、正文疯狂闪烁。 | 触发宿主全量排版重排算法，强行篡改了宿主内部的视口滚动锚点。 | **冷热解耦**：全量元数据内存直出；悬停 100% 纯读，绝不触发点击。 |
| **AP-03** | **粗粒度固定轮询等待** | 点击早期折叠卡片时，出现明显迟滞与卡顿（约 1 秒延迟）。 | 固定延时（如 `sleep 260ms`）与宿主实际渲染节奏脱节，多次重试累积等待时间。 | **微任务侦听**：使用 `MutationObserver` 侦听宿主 DOM 插入，118ms 瞬时捕获并直达。 |
| **AP-04** | **每次渲染粗暴重建 innerHTML** | 鼠标划过卡片时列表闪烁，滚动条位置被反复重置回顶部。 | 销毁已有 DOM 导致浏览器重新布局（Reflow），丢失滚动状态。 | **特征签名守卫**：比对 `dataset.renderedSignature`，无新轮次时仅执行类名微调。 |
| **AP-05** | **在会话层启动常驻 Daemon** | 宿主界面出现常驻后台任务旋转卡片，引发界面干扰与资源疑虑。 | 带常驻守护标识（Daemon）的进程会被宿主前端渲染为未完成的阻塞任务。 | **系统托管**：Sidecar 引擎由宿主插件系统在系统底层静默托管（`sidecar.json`），绝不在会话层挂起。 |
| **AP-06** | **使用含瞬态 Query 的 URL 作为会话真理** | 视口滚动或参数变动后，时间线卡片从全量骤降回 2~3 轮。 | 宿主滚动会写入 `?section=...`，以此作为 SessionKey 导致频繁误清空缓存，且 Sidecar 缓存拦截阻断了回推。 | **单一真理 ID**：以 `convId` 作为唯一会话判断；客户端显式请求时 Sidecar 必须无条件 `force` 推送全量数据。 |
| **AP-07** | **零防抖悬停与整屏伪元素桥接** | 鼠标划过屏幕右侧即误弹大菜单，且移开后无法自动关闭。 | 无 Hover Intent 防抖导致 1ms 划过即弹出，72vh 高度的透明 `::after` 桥接伪元素侵占视口热区，且缺失全局失焦与外部点击关闭。 | **意图防抖与安全看门狗**：手柄 110ms 意图防抖；收敛伪元素桥接；挂载 Click Outside、ESC、Window Blur 与全局坐标看门狗。 |
| **AP-08** | **单点绑定局部视口容器与固定死时限守护** | 点击切换新会话后，多数会话依然被宿主强推到对话末尾/最底部。 | SPA 切换时宿主销毁旧视口 DOM 导致局部 Observer 永久失灵脱管；固定 2.2 秒死延时在长会话异步渲染时提前超时，未能阻断宿主后续的延迟 autoscroll。 | **Body 级生命周期感应与动态就绪收敛**：全局 `document.body` 级 Observer 穿透感应新视口并即时绑定；结合卡片就绪感应与 1800ms 平息收敛守护。 |
| **AP-09** | **会话 ID 探测单纯依赖 URL pathname** | 侧边栏点击切换会话时插件完全失感，锚定机制与数据拉取不触发。 | Electron 桌面宿主中路由采用内存 History，`window.location.pathname` 绝大多数时候恒为 `"/"`。 | **多源级联探测**：以 `[data-cascade-id]`（视图容器与侧边栏选中行）为首要真理，结合正则提取级联兜底。 |
| **AP-10** | **凭挂载卡片总数判定新提问 & 主动跳转未解绑视口锁定** | 1. 处于末轮点击其他轮次无效；<br>2. 处于倒数第二轮点击跳转倒数第三轮时被强推回末轮。 | 展开顶部折叠历史导致 `userCards.length` 变大，被粗暴误判为“用户发送了新提问”并强推到底部 `lastCard`；同时点击跳转未解除 `sessionArrivalPending` 与 `streamLockActive`，且 DOM 卡片中附带引用胶囊导致折叠状态失配。 | **末尾卡片特征指纹比对 + 主动导航全量解绑 + 胶囊剥离纯净匹配**：仅在末尾卡片内容实质改变时触发新提问锚定；点击跳转即刻标记 `isNavigatingTurn = true` 并解除守护锁定；剥离 DOM 引用胶囊进行双向前缀匹配与倒序序数对齐。 |
| **AP-11** | **耦合排版工具类名与空会话状态机漏判** | 1. 宿主排版微调后点击跳转与到达锚定全面失效，页面仍滚到最底；<br>2. 新开对话仍显示上一会话的“共 28 轮交互”，悬停误弹旧菜单。 | 选择器硬编码耦合排版工具类名（`pt-4`），宿主改为 `pt-6` 后卡片抓取为空；会话同步状态机在 `activeConvId === ''` 时忽略重置，旧数据常驻。 | **语义选择器嵌套去重 + 空会话全量重置与悬停静默**：`getUserCards` 基于 `data-testid` 与特征组提取并过滤子代嵌套；空会话主动推流 `[]`，重置全部指针，悬停静默且显式点击展示 0 轮。 |
| **AP-12** | **全文档盲查加载按钮 & 假死早退退出循环** | 处于早期折叠轮次点击卡片展开失败，卡死在加载态并不做跳转。 | `findLoadOlderBtn` 未限定在当前视口内，误命中辅助侧面板按钮；且一旦按钮在加载期间被 React 设为 `disabled`，循环直接 `break` 中断退出，未能轮询等待卡片载入。 | **视口作用域收敛 + 繁忙态自适应轮询与状态比对**：仅在 `getViewport()` 内检索加载按钮；当按钮为 `disabled` 时最多等待 1200ms 解除，并通过 `aria-label` 与卡片数比对确认新批次已渲染完毕后再行跳转。 |

## 深度剖析（Why it failed）

### AP-01：为什么不能依赖前端 DOM 提取会话？
Antigravity 采用基于 React 的长列表虚拟化渲染。当对话超过一定长度时，宿主会自动卸载离开视口的上方历史消息，并在顶部渲染一个 `Load older messages` 按钮。
如果在前端用 `document.querySelectorAll('div[class*="group/user-input-step"]')` 读取数据，只能拿到当前挂载的 2~3 轮，丢失全部早期历史。

### AP-02：为什么悬停时绝不能自动点击 `loadBtn.click()`？
此前试图在用户鼠标悬停时间线手柄时，自动递归调用 `loadBtn.click()` 展开历史。
由于宿主在加载早期历史后，内部逻辑会主动将视口拉到新插入的消息位置（例如第 2 轮），导致用户正在看的最新对话突然被强行甩飞，伴随全局高度反复重排抖动。
**铁律：鼠标悬停展开时间线，必须是 100% 纯读动作，主视口位移严格为 0。**

### AP-03：为什么等待 DOM 插入不能用 `setTimeout`？
宿主处理点击加载历史消息时，从发起内部数据检索到向 DOM 插入节点，耗时约为 110ms ~ 120ms。
如果采用固定 `sleep(260ms)` 轮询，每轮循环不仅白白等待，而且容易在跨轮次判断时产生阶梯式延迟（累积达到 800ms ~ 1000ms）。改用 `MutationObserver` 挂载在主视口容器上，可在节点挂载完成的瞬间立刻触发微任务回调，等待时间大幅缩短至 150ms 左右。

### AP-06：为什么不能将 `window.location.search` 纳入会话键判定？
Antigravity 宿主视口在滚动、查看不同章节或打开侧栏设置时，会自动在 URL 上动态追加 `?section=...` 或其他 query 参数。如果将带有 query 的完整路径作为会话真理键，每一次滚动都会误判为会话切换，将内存中的全量历史粗暴清空。而由于 Sidecar 引擎的推送签名未变，客户端发起的补偿请求会被 Sidecar 直接忽略，导致客户端最终退化回前端 DOM 刮取，丢失绝大部分历史轮次。必须以正则提取的会话唯一标识 `convId` 作为单一真理。

### AP-07：为什么悬停展开必须具备 Hover Intent 与失焦看门狗？
若只要光标触碰到手柄的 1 个像素就立即打开弹出层，用户在移动鼠标跨屏、拖动滚动条或点击右侧操作项时，会在毫无意图的情况下频繁受到菜单弹窗干扰。同时，如果依赖传统的 `mouseleave` 事件，浏览器在快速划过或子元素重建时极易丢失离开通知；配合原本高达 72vh 的伪元素桥接，会导致弹窗死锁在屏幕上无法关闭。必须建立 110ms 的停留防抖、收敛桥接区域，并结合外部点击（Click Outside）、ESC 键与全局物理坐标移动看门狗构成多重闭环保护。

### AP-08：为什么不能只监听初始视口且不能使用固定死时限守护？
Antigravity 客户端在切换会话时，旧的 `autoscroll-viewport` DOM 容器会被 React 彻底销毁卸载，并异步创建挂载一个全新节点。若 `MutationObserver` 仅绑定在 `initialViewport` 上，旧节点销毁后插件就会完全脱管，再也收不到任何子树变动事件。同时，长会话的异步排版与渲染往往耗时 1.5~2.5 秒，若仅设置 2.2 秒死延时，守护循环在卡片尚未挂载完全时便已提前超时终止，随后宿主原生的 autoscroll 钩子便会长驱直入把页面推至最底部。必须采用全局 `document.body` 级的穿透感应动态接管新视口，并实施“卡片就绪感应 + 1800ms 平息收敛”的动态防回弹机制。

### AP-09：为什么会话 ID 探测不能单纯依赖 window.location.pathname？
在 Antigravity 宿主 Electron 容器内，侧边栏点击切换会话主要依托 React Router 的内部状态流转，大部分时候 `window.location.pathname` 始终恒定保持为 `"/"`，不会同步更新为 `/c/<id>`。若仅凭 `pathname` 提取会话，绝大多数会话中获取到的均为空字符串，导致无法向 Sidecar 拉取全量轮次，也无法及时触发到达守护控制器。必须以 `[data-testid="conversation-view"]` 及侧边栏激活行上的 `data-cascade-id` 属性作为首要来源，辅以正则级联兜底。

### AP-10：为什么绝不能仅凭 DOM 卡片数量判定新提问？
在 React 虚拟化长列表中，Antigravity 默认仅渲染离开视口最近的 2~3 轮对话，较早历史被折叠在顶部的 `Load older messages` 按钮后。
当用户在时间线中点击较早轮次时，插件会按需触发 `loadBtn.click()`。此时早期消息被插入在视口**顶部**，导致 DOM 中的卡片总数（`userCards.length`）从 2 轮激增至 4 轮或更多。
若代码仅通过 `currentCount > lastKnownTurnCount` 判定“是否有新提问”，就会将“展开历史”灾难性地误判为“用户发送了新提问”，从而立刻执行 `scrollToElement(viewport, lastCard)` 将视口粗暴拽回最底部的末轮！
同理，用户主动点击时间线属于明确的人工意图导航，必须即刻撤销 `sessionArrivalPending` 与 `streamLockActive`，并以 `isNavigatingTurn` 阻断一切后台 autoscroll 看门狗；在文本匹配层面，必须剥离 `.context-scope-mention` 等引用胶囊以恢复纯净提问，并结合前后双向包含匹配与倒序序数对齐，彻底消除折叠状态误判与多重死锁。

### AP-11：为什么绝不能将 DOM 节点选择器耦合至排版工具类名？
宿主应用升级迭代过程中，界面布局排版参数极易发生样式微调（例如将用户卡片的 padding-top 从 `pt-4` 提升为 `pt-6`）。
若选择器硬编码形如 `div[class*="pt-4"]`，宿主一旦调整 class，DOM 提问卡片采集结果将直接归零，导致两大灾难性故障：
1. **定位完全瘫痪**：由于找不到当前视口中已挂载的对应卡片，所有点击历史跳转均无法找到目标节点，退化为无响应；
2. **到达锚定彻底失守**：会话进入守护控制器（`checkAndApplyArrivalAnchor`）因无法定位末轮卡片头部，直接导致视口失控，被宿主原生 autoscroll 强推至对话最末尾。
同时，会话同步状态机若仅判断 `if (activeConvId && activeConvId !== currentConvId)`，则在用户点击新建对话（`activeConvId === ''`）时会完全漏判，导致上一个会话解析出的几十轮历史卡片与签名依然常驻内存，不仅出现“共 28 轮交互”的历史错乱，而且在鼠标悬停时弹出空会话菜单。
**铁律**：必须通过 `getUserCards()` 以语义化属性（`data-testid="user-input-step"`）与特征类（`group/user-input-step`）联合查询并过滤嵌套子节点，杜绝任何布局工具类名绑定；在进入新会话（`activeConvId === ''`）时必须执行彻底的状态清理与空数据推流，手柄挂载 `.is-empty`，且对 0 轮交互执行悬停静默保护。
